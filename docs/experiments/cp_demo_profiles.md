# Демо-профили Color Precision: формат и эталоны реперных цветов

14.10.2026. Набор: демо-профили Color Precision для Lightroom/ACR (папка от Алексея, копия в `data/raw/cp_demo/`, вне git).
Скрипты: `tools/cp_demo/crs_table.py` (раскодирование), `tools/cp_demo/measure.py` (замер). Таблицы: `data/derived/cp_demo_patches.csv`,
`data/derived/cp_demo_anchors.csv`. Установщики не запускались.

## Формат (раскодирован)
- Профиль — XMP «Look» (`crs:PresetType="Look"`), ссылка `crs:RGBTable="<hash>"` на `crs:Table_<hash>="…"`. LookTable в этих файлах нет.
- Кодировка строки — как в Adobe DNG SDK (`dng_big_table.cpp`): base85 со своим алфавитом (`0-9a-zA-Z.-:+=^!/*?`'|()[]{}@%$#`), 4 байта → 5 знаков,
  младший разряд первым; внутри — 4 байта длины (little-endian) + zlib. Код написан здесь, по описанию; исходник SDK в сети не нашёл
  (зеркало не отдало файлы), формат подтверждён тем, что zlib распаковал ровно заявленную длину во всех 96 файлах.
- Содержимое: тип 1 (RGB-таблица), версия 1, **3D-куб 32×32×32**, значения — int16-поправки к тождественной сетке (выход = узел + поправка),
  порядок осей R (внешняя) → G → B. Хвост: primaries = 2, gamma = 2, gamut = 0 (обрезка), «Amount» 0…200 %.
- Пространство: primaries 2 / gamma 2 прочитаны как **ProPhoto (D50), гамма 1.8** — по порядку перечислений в SDK, как я его помню;
  **с исходником не сверено**. Чувствительность: если вместо этого считать sRGB, кожа сдвигается на 1–2 единицы a/b — выводы ниже не меняются.
- Проверка порядка осей: при R-внешней медиана ΔE2000 на 18 цветных патчах 7.0, при переставленной — 36.3. Принят первый.
- **Portra 400 (оба сканера) — не только таблица:** в XMP ещё HSL-ползунки (насыщенность красных +46, оранжевых +17 и т. д., у Frontier и Noritsu разные)
  и тоновые кривые (общая + R/G/B). Их я **не применял** (алгоритм HSL у Adobe закрытый, порядок применения не известен). Числа Portra ниже —
  «только таблица», полный вид профиля другой. У остальных 6 профилей кроме таблицы ничего нет.
- Камерные варианты (12 папок) — другие таблицы: совпадают с nonRAW только Fuji 4/8 и Nikon Z 2/8. Камерные таблицы рассчитаны на вход
  конкретной камеры, здесь не мерены.

подтверждением атласа это не считать — HSL-часть Portra не применена, мишени разные (CC24 и SG), вход профилей цифровой, патчей на сектор мало.

## Pro 400H относительно Portra 400 (нет в PDF-атласе)
На обоих сканерах Pro 400H насыщеннее таблицы Portra почти везде: красно-оранжевые ×1.7, голубые ×1.55, светлее на 3–6 L в тёплых секторах.
Сдвиг оттенка в синих 240–300°: +19° (F) / +33° (N), в 300–360° +9…+13°. Сравнение с «только таблицей» Portra — с поправкой на неучтённые HSL (+46 к красным):
по насыщенности красных разрыв частично закроется, насколько — не мерено.

## Оговорки
- Пространство таблицы (ProPhoto, гамма 1.8) — вывод из перечислений, не сверено с исходником SDK; чувствительность 1–2 единицы a/b.
- Portra 400 — без HSL и тоновых кривых профиля. Amount = 100 %. Профиль применяется к «nonRAW» (JPEG/TIFF), т. е. вход — уже отрендеренное изображение;
  считать, что ColorChecker в ProPhoto и есть такой вход, — допущение.
- Интерполяция трилинейная (что использует ACR — не знаю; на 32 узлах разница мала, не мерено).
- Права на профили не известны (коммерческий продукт, демо-версия); в git только наши числа.
